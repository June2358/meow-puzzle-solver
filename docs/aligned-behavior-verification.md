# 공통 동작 정렬 검증 — 2026-10-24

기준 커밋은 `ee96e80`이다. 알고리즘과 고유 편집을 유지하면서 결과 정책,
표시용 데이터 전달, 화면 배치와 공통 조작의 차이를 정리했다.

## 달라진 동작과 데이터

- 앱은 `PlaybackData(outcome, frames)`를 받는다. 해 분류는 UNIQUE/MULTIPLE/UNSOLVABLE로
  통일하며, 실제 단계는 기존 퍼즐 자료형을 유지한다. Sudoku의 steps tuple은 복사하지 않는다.
- 해가 없으면 양쪽 모두 같은 메시지와 원본 초안으로 입력 화면에 복귀한다.
- 공통 재생기가 현재 단계를 한 번 선택하고 같은 객체를 보드와 설명에 전달한다.
  앱별 결과 배지와 배치 계산을 공통 엔진으로 옮겼다.
- 입력/재생의 창1010×700, 패널350×560, 보드 영역540과 작은 안내 글꼴15가 같다.
  숫자·후보 및 고양이·영역 표현은 유지한다.
- 양쪽 첫 방향키/Tab은 첫 칸을 선택하고 Tab/Shift+Tab은 양 끝에서 멈춘다.
  Ctrl/Alt/GUI 조합이 삭제·숫자 입력·시작으로 오인되지 않는다. Ctrl+V JSON 입력,
  MEOW 크기 필드/영역 알파벳, Sudoku 단독 C/R/S는 유지한다.
- 같은 값을 다시 입력하면 기존 오류/안내가 유지된다.

## 실제 브라우저

로컬 웹 빌드에서 양쪽 입력/재생이 같은 크기와 배치를 사용하는 것을 확인했다.
양쪽 첫 방향키→Tab→실제 칸 편집, MEOW 해 없음의 편집 복귀, Sudoku의 해 없음
복귀와 동일한 오류 문구, 잘못된 JSON의 오류/입력문 보존을 확인했다.
MEOW 길게 누르기 이동, 양쪽 프리셋 풀이/최종 단계/편집 복귀와 초안 보존,
Sudoku의 Ctrl+R/Ctrl+S 입력 보존과 자동 재생 재시작/마지막 정지도 확인했다.
양쪽 브라우저 콘솔 오류는 없었다.

## 보존 범위

양쪽 앱의 기존 파일 중 app/input_dialog/visualizer를 제외한29개 파일은
기준 커밋과 개행을 정규화한 바이트가 동일하다. 솔버·모델·타임라인·파서·프리셋과
기존 보드 글꼴 설정은 유지됐다. 원본 형제 저장소 두 개도 변경 없이 깨끗하다.
공통 모듈이 퍼즐 패키지를 import하지 않음을 AST로 확인했다.

추적 Python 물리적 줄 수는 실행 코드6,954, 테스트4,084다. 직전 대비 실행 코드는
34줄 늘었으며, 결과 계약과 배치 기준이 추가된 대신 앱별 연결/표현 코드가 줄었다.
이번 변경의 기준은 줄 수 감소가 아니라 같은 정책과 데이터 흐름의 실제 사용이다.
