# 공통 화면 리팩터링 검증 — 2026-10-23

기준은 최초 통합 커밋 `91acfeb`이다. 입력 화면, 풀이 재생 화면, 앱 수명주기를
공통 구현으로 옮기고 두 앱을 실제 호출자로 연결했다. 구조와 수정 위치는
[architecture.md](architecture.md)에 정리했다.

## 검증 결과

- `uv run --locked python -m pytest -q -W error`: 198 passed, 1 skipped.
  건너뛴 한 검사는 Windows 심볼릭 링크 권한에 의존하는 기존 빌드 경로 검사다.
- `uv run --locked ruff check --no-cache .`: 통과.
- `uv run --locked ruff format --check .`: 93개 파일 통과.
- `uv run --locked --group web python scripts/build_web.py`: 두 실제 Pygbag 빌드 통과.
  각 APK의 `assets/`에는 해당 앱, 공통 모듈, 프리셋과 폰트·라이선스가 들어 있다.
  테스트나 반대쪽 앱은 포함되지 않는다.
- SDL dummy 환경에서 실제 `python -m meow`, `python -m sudoku` 진입점을 실행해
  화면 생성, QUIT 이벤트 처리와 pygame 종료를 확인했다.
- 로컬 웹 빌드를 실제 브라우저에서 실행했다. MEOW 크기 편집·영역 입력·드래그,
  Sudoku 숫자 편집·중복 표시, 양쪽 JSON 오류/입력문 보존/불러오기와 전사 프롬프트,
  풀이 시작·단계 이동·최종 해·편집 복귀 후 원본 초안 보존을 확인했다.
  MEOW 키 길게 누르기와 자동 재생의 마지막 단계 정지도 확인했다.
  양쪽 브라우저 콘솔 오류는 없었다.

## 독립 검토와 회귀 수정

독립 검토에서 12개 프리셋의 388개 프레임을 렌더링하고 공통 조작 검사를 실행했다.
공통 모듈에는 퍼즐 패키지 import나 앱 이름 분기가 없으며, 중복된 비도메인
실행 흐름이 남아 있지 않음을 확인했다.

복수해 경고와 활성 가정을 함께 표시할 때 Sudoku의 짧은 풀이 사유가 `…`로만
나오던 문제를 발견했다. 실제 복수해 사례의 두 단계에서 글꼴 렌더링을 관찰하는
회귀 검사가 먼저 실패함을 확인했다. 활성 가정을 한 줄로 표시해 28px을 확보한
뒤 36개 재생 검사가 통과했다. 독립 재검토와 실제 브라우저에서도 사유 두 줄,
확정 내역, 활성 가정과 조작 안내가 겹치지 않고 보이는 것을 확인했다.

## 코드 길이와 보존 범위

Git 추적 Python 파일의 물리적 줄 수이며 빈 줄과 주석을 포함한다.
문서·설정·자산·생성된 빌드 파일은 제외한다.

| 구분 | 원본 두 저장소 합계 | 최초 통합 `91acfeb` | 공통 화면 리팩터링 |
| --- | ---: | ---: | ---: |
| 실행 코드 | 8,328 | 7,769 | 6,920 |
| 테스트 | 2,603 | 2,964 | 3,555 |
| 합계 | 10,931 | 10,733 | 10,475 |

실행 코드는 원본 대비 1,408줄(16.9%), 최초 통합 대비 849줄(10.9%) 줄었다.
공통 화면의 모달 정리·키 반복·자동 재생·오류 복귀를 검사하면서 테스트는 늘었다.
퍼즐별 규칙·자료형·검증·편집 의미·보드 표현과 단계 해석은 어댑터에 유지한다.

17개 알고리즘/모델/타임라인/입력 초안/프롬프트 파일을 AST로 비교했다.
공통 `cell_name` 함수 추출과 import 변경을 제외한 본문은 동일하다.
파서의 스키마 검증, 프리셋 검증 함수와 프리셋 데이터도 유지한다.
원본 두 저장소는 변경 없이 깨끗하며, 두 원본 HEAD는 통합 저장소의 조상이다.

## 확인하지 않은 범위

실제 운영체제 클립보드, 모바일/다른 브라우저, 실제 그래픽 하드웨어는 확인하지
않았다. 긴 설명/많은 효과의 패널 말줄임은 유지한다. 원격 저장소 생성·push·배포는
수행하지 않았다.
