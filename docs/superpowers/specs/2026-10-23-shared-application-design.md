# 공통 애플리케이션 구조

사용자 요청: 사실상 알고리즘 부분만 차이를 두고 나머지는 최대한 공통화한다.

## 결정

이전 통합의 유틸 공유를 넘어 입력 화면과 풀이 재생 화면을 각각 하나의 공통 구현으로 만든다. 각 앱은 공통 화면을 사용하는 퍼즐 어댑터다. 통째로 복사된 메서드나 같은 동작을 두 곳에 남기는 것보다 작은 공통 구현에 실제로 연결하는 것을 우선한다.

공통 입력 화면은 레이아웃/패널/버튼/메시지/설명, 프리셋 조작, JSON·프롬프트·클립보드 수명주기, 이벤트 분배와 비동기 프레임 루프를 담당한다. 퍼즐 어댑터는 초깃값, 보드 그리기, 키 입력 규칙, JSON 파서와 유효성 검사를 담당한다.

공통 재생 화면은 화면·패널·버튼 구성, 텍스트와 효과 목록 출력, 이전/다음/Home/End, 키·마우스 누르기 반복, 자동 재생, 포커스 해제와 종료, 비동기 이벤트 루프를 담당한다. 퍼즐 어댑터는 알고리즘 기록을 표시 자료로 변환하고 보드/후보/근거를 그린다. 공통 코드에는 meow/sudoku 이름 분기나 퍼즐 모듈 import를 넣지 않는다.

앱 시작·편집·풀이·결과·편집 복귀·오류·pygame 종료 흐름도 하나로 관리한다. 프리셋 파일 읽기처럼 도메인과 무관한 나머지 중복도 합친다.

## 유지할 동작

두 알고리즘, 모델, JSON 계약, 입력/가정/해 분류/단계 기록 의미는 유지한다. MEOW 영역 편집·크기·드래그와 Sudoku 숫자 편집·충돌 표시는 유지한다. 잘못된 입력은 원본 보드·입력문을 보존한다. 복수해 경고, 활성 가정·추론 근거·적용 내역·관련 영역 색상 칩을 유지한다. 웹과 데스크톱 실행 및 기존 앱별 폰트 크기를 유지한다. 공통 패널 스타일과 조작 안내는 일관되게 맞출 수 있다.

새 의존성과 공개 배포는 추가하지 않는다. 두 원본 저장소는 변경하지 않는다.

## 검증

기존 회귀 검사 전체, 두 앱에 걸친 공통 제어 동작 검사, 실제 두 Pygbag 빌드/번들 검사, 브라우저 입력·오류·풀이·키/버튼 이동·편집 복귀를 확인한다. 변경 전후 실행 코드/테스트 줄 수와 공통 모듈이 맡은 동작을 기록한다. 단순히 기존 코드를 새 디렉터리로 옮긴 상태를 완료로 보지 않는다.
