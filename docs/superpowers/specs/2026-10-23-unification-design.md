# Puzzle Solvers 통합 설계

사용자가 승인한 범위: 현재 기능과 화면을 유지하며 두 저장소와 공통 기반을 통합한다. 기존 웹 주소 유지와 기능 추가는 범위에 포함하지 않는다.

## 접근 방법

- 선택: 하나의 저장소에서 `meow`, `sudoku`, `puzzle_common`을 함께 관리한다. 공통 수정과 양쪽 검사를 한 번에 실행할 수 있다.
- 대안: 별도의 공통 패키지를 두 저장소가 버전으로 참조한다. 독립 배포에는 좋지만 이번 목표에는 패키지 배포와 버전 갱신 부담이 추가된다.

## 구조와 제약

- 새 로컬 `puzzle-solvers` 저장소/작업 브랜치에서 작업하고, 두 원본 폴더는 보존한다. 두 프로젝트의 Git 이력도 보존한다.
- 루트 `meow/`, `sudoku/` 패키지와 `python -m meow`, `python -m sudoku` 실행 방식을 유지한다.
- 버튼, 프레임 처리, 폰트 로딩/자산, 색상, 텍스트 줄바꿈, 클립보드, 브라우저 텍스트 입력을 공통 모듈로 이동한다.
- 퍼즐별 입력 JSON 형식, 프롬프트, 폰트 크기, 보드 그리기, 모델, 풀이 정책과 시각화 내용은 유지한다.
- Python 3.12.2, pygame-ce 2.5.8, pytest 9.1.1, ruff 0.16.4, pygbag 0.9.2를 유지하고 새 의존성은 추가하지 않는다.
- 테스트 이름 충돌은 pytest importlib 모드로 해소하고 기존 회귀 검사를 유지한다.
- 웹은 각 앱의 진입점 + 앱 패키지 + 공통 패키지/자산을 독립 번들에 포함한다. 하나의 `build/web` 아래 `meow/`, `sudoku/`와 최소 선택 페이지를 배치한다.
- CI와 Pages workflow는 각각 하나로 통합한다. 원격 저장소 생성/푸시와 실제 게시 작업은 이번 로컬 통합에 포함하지 않는다.

## 완료 증거

전체 Ruff/포맷/pytest 검사 통과, 두 웹 번들 안의 공통 코드와 폰트 포함 확인, 두 앱의 실제 브라우저 실행/기본 입력·풀이·단계 이동 확인, 원본 저장소 변경 없음과 두 원본 커밋의 조상 관계 확인.
