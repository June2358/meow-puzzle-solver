# 공통 동작과 표시 데이터 정렬

사용자는 알고리즘과 퍼즐 고유 동작을 유지하면서, 기존 공통 구현을 이용해
묘하게 다른 동작과 데이터 전달 방식을 먼저 최대한 통일하도록 지시했다.
앞서 논의한 단계적 정렬 방식을 선택한 실행 요청이다.

## 접근과 범위

현재 두 화면 엔진을 전부 다시 쓰는 방법보다, 검증된 엔진에 공통 결과/단계 계약을
연결하는 방법을 택한다. 단일 앱 진입점·GitHub 게시·알고리즘 재작성은 이번 범위가 아니다.
기존 앱별 결과를 UI에서 직접 해석하는 연결은 제거한다.

## 공통 계약

- `puzzle_common.presentation.Outcome`: UNIQUE, MULTIPLE, UNSOLVABLE.
- `PlaybackData[Frame]`: frozen 데이터, outcome과 비어 있지 않은 tuple frames.
  Frame은 기존 MEOW PlaybackFrame 또는 Sudoku SolveStep이며 내부 상태를 복제하지 않는다.
- 양쪽 `presentation.to_playback(result)`가 순수 변환을 맡는다. MEOW는 기존
  build_timeline을 사용하고 Sudoku는 기존 steps tuple을 그대로 전달한다.
- run_app은 정규화된 결과만 받고 해 없음 정책을 한 번만 적용한다.
  메시지: `현재 입력으로 가능한 해가 없습니다. 원본 문제와 입력을 확인하세요.`
  원본 입력을 보존해 편집기로 복귀한다. 유일해/복수해는 재생한다.
- 재생 엔진은 동일한 현재 Frame을 보드와 설명에 전달하고 인덱스를 단독 소유한다.
  해 분류 배지는 공통 엔진에서 표시한다. 퍼즐별 자료형과 추론 의미는 유지한다.

## 공통 사용감

- 화면 배치 정책은 한 곳: 보드 영역540, 좌우 여백45, 보드 시작Y70, 패널 간격30,
  패널 너비350, 창 높이700. 창 너비1010. 패널 높이560.
  격자는 540을 크기로 나눈 정수 셀 크기로 맞추고 영역 안에서 가운데 배치한다.
- 입력/재생이 같은 배치를 사용한다. 보드 숫자/후보 글꼴은 기존 크기를 유지하고,
  공통 안내·메시지·작은 라벨용 info 글꼴은15로 통일한다.
- 양쪽 방향키는 선택이 없으면 첫 칸을 선택한다. Tab/Shift+Tab은 칸 순서대로
  이동하고 양 끝에서 멈춘다. MEOW 크기 필드의 키 우선 처리를 유지한다.
- Ctrl/Alt/GUI 조합은 보드 편집/삭제/풀이 시작으로 흘러가지 않는다. Ctrl+V의
  기존 JSON 기능은 유지한다. Sudoku의 단독 C/R/S와 MEOW A~Z 입력은 유지한다.
- 동일한 값을 다시 입력해도 기존 오류/안내가 사라지지 않는다.
- 격자 좌표와 셀 사각형/채우기/테두리 계산은 공통 엔진을 사용한다.

## 보존과 완료 기준

솔버·모델·타임라인 생성·파서·프리셋 데이터와 검증 계약은 변경하지 않는다.
영역 드래그/가변 크기와 숫자/중복/후보 표시, 추론 근거·활성 가정·관련 색상은 보존한다.
새 의존성을 추가하지 않는다. 공통 모듈은 퍼즐 패키지를 import하거나 이름으로 분기하지 않는다.
의도적 정책 변경은 해 없음의 편집 복귀와 위 공통 조작/배치뿐이다.
양쪽 실제 입력/재생을 대상으로 회귀 검사, 전체 검사, 실제 웹 빌드 및 브라우저 확인을 한다.
