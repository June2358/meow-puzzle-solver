# 하나의 퍼즐 앱

## 승인된 목표

사용자는 화면·조작·내부 구조를 모두 통일하고 풀이 규칙과 해 판정은 유지하는 방향을 선택했다.
기존 배포본 f993f23을 기준으로 별도 브랜치에서 구현한다.

## 선택한 접근

기존 Pygame/Pygbag와 검증된 공통 Engine을 유지하면서 입력기·재생기·보드 렌더러·
진입점·웹 번들을 각각 하나로 만든다. 단순히 기존 두 화면을 선택하는 실행기는 목표를
충족하지 않는다. 새로운 웹 프레임워크나 원격 플러그인 설치는 필요하지 않다.

퍼즐 모듈은 규칙, 파서, 알고리즘, 해 판정과 원본 프레임을 표시 데이터로 변환하는
순수 함수를 제공한다. 화면 클래스나 pygame 그리기/이벤트 처리는 제공하지 않는다.
공통 화면은 퍼즐 이름이나 네이티브 상태형으로 분기하지 않는다.

## 공통 계약

- `puzzle_common/view.py`: 불변 CellMark, CellView, BoardView, PlaybackDetails.
  표시 요소는 글자·고양이·X, 후보 위치, 색·강조·테두리와 영역 번호로 제한한다.
- `puzzle_common/puzzle.py`: PuzzleDefinition. 제목/기호/빈칸/크기/프리셋/프롬프트와
  normalize/parse/create/solve/grid/editor_view/frame_view/describe/validate_frames를 등록한다.
- `puzzle_common/board.py`: 두 퍼즐이 함께 사용하는 유일한 보드 렌더러.
- `puzzle_common/input_dialog.py`: 동일한 편집 버퍼와 이동/입력/삭제/드래그/크기/JSON 처리.
- `puzzle_common/playback.py`: 기존 단계 이동·자동 재생을 유지하는 유일한 재생 화면.
- `puzzle_common/app.py`, `main.py`: 앱 내 퍼즐 선택 → 편집 → 풀이 → 재생.
  편집 Esc는 선택으로, 재생 Esc는 원본 편집으로, 창 닫기는 앱 종료로 동작한다.
- `scripts/build_web.py`: 양쪽 퍼즐과 공통 코드를 담은 번들을 한 번 빌드한다.
  기존 `/meow/`, `/sudoku/` 주소는 같은 앱의 해당 모드로 연결한다.

## 유지할 의미와 검증

Engine/SolveResult/build_frames와 원본 알고리즘 기록을 그대로 사용하며 별도 타임라인을 만들지 않는다.
MEOW의 독립 exact 판정과 Sudoku의 두 해 확인, 후보 순서·추론·반증 의미를 유지한다.
잘못된 JSON은 편집 초안을 보존한다. 외래 퍼즐의 풀이 기록은 화면 생성 전에 거부한다.
MEOW의 가변 영역/색/고양이, Sudoku의 초기 숫자/후보/근거/제거 후보 표시를 유지한다.
화면 배치·단축키·픽셀 일치는 요구하지 않는다. 두 퍼즐은 같은 조작을 사용한다.

검사는 기존 알고리즘·파서·실행 기록 검사를 유지하고, 옛 화면 클래스/두 번들에 결합된 검사는
실제 새 공통 화면과 단일 번들 검사로 교체한다. 전체 Ruff/pytest, 웹 빌드, 브라우저에서
두 모드의 입력·풀이·편집 복귀·선택 전환을 확인한다.

## 범위

새 퍼즐·플러그인 자동 탐색·외부 의존성·새 풀이 기법은 추가하지 않는다.
이번 새 구조는 작업 브랜치에서 검증하고 사용자가 검토할 수 있게 제시한다.
